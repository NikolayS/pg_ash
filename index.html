pg_ash 2.0
reader api

A minimal, composable analysis surface for Postgres active-session history — one load unit, one time convention, one drill grammar. Built for humans in psql and AI agents driving investigations.

CPU* IO Lock LWLock IPC unit = AAS, average active sessions
25×2 → 7+2

v1.x shipped ~25 readers, each duplicated as f() / f_at(). 2.0 is seven data functions plus two render helpers.

1

load unit everywhere: avg_aas · peak_aas · p99_aas. No more samples vs backend_seconds confusion.

p_from, p_to

one time convention; defaults mean "the last hour" (report: the last day). The _at twins are gone.

0

silent empty results. Data readers report the source they used; unanswerable drills raise (report degrades by omitting keys), with the retention boundary named.

§1

the investigation arc

Every incident walks the same path — broad → locate → drill → leaf. Each step is one function, and every function speaks the same parameter grammar, so the next call is always obvious (to an engineer, or to an agent reading catalog comments).

US-1TRIAGE"Is it bad? Spike or sustained?"ash.periods()
US-2LOCATE"When did it spike?"ash.timeline(…)
US-3DRILL"Wait type → event → query — with p99 on every row."ash.top(dimension, …)
US-4LEAF"For this wait event, which queries?"ash.aas(event) + top('query_id', …)

the surface

one grammar, whole investigation

-- 1 · broad: is load high? spiky?
select * from ash.periods();

-- 2 · when? (order the worst buckets first)
select * from ash.timeline(p_from => now() - '1 day'::interval)
order by peak_aas desc;

-- 3 · what? drill L1 → L2 inside the spike window
select * from ash.top('wait_event_type', p_from => :t0, p_to => :t1);
select * from ash.top('wait_event',
        p_wait_event_type => 'IO', p_from => :t0, p_to => :t1);

-- 4 · leaf: which queries drive DataFileRead?
select * from ash.top('query_id',
        p_wait_event => 'DataFileRead', p_from => :t0, p_to => :t1);

machine ingest — ash.report()

{
  "aas_avg":     {"total": 29.6, "cpu": 12.4, "io": 8.9,
                  "ipc": 4.1, "lock": 3.2, "lwlock": 1.0},
  "aas_worst1m": { … }, "aas_p99": { … }, "aas_p999": { … },
  "top_events_worst1m":  {"io": ["DataFileRead(89.0)", …], …},
  "top_queryids_worst1m":{"total": ["8231…417(12.3)", …], …}
}

Per-wait-class avg, worst-1-minute, p99, p99.9 — 1-minute resolution, zero-filled — plus top events and top query ids per extreme window. total sums the five real-load classes and excludes Activity, Client and Timeout, so it can trail the full top('wait_event_type') list. Raw AAS only: scoring, thresholds, vCPU normalization are the consumer's job. Contract is frozen: keys are only ever added.

§4

principles

AAS is the only unit

Every reader reports avg_aas, peak_aas, p99_aas; backend_seconds rides along as the absolute. The three v1.x units are gone.

one time convention

p_from / p_to, defaulting to the last hour. Dropping the f/f_at twins alone halves the surface.

dimensions are parameters

Group-by is an argument of top; filters are uniform named parameters. Six v1.x drill functions collapse into one grammar.

data ≠ presentation

Data functions return typed columns only. Bars, colors and charts live in exactly two human helpers: chart and summary.

source honesty

Data readers auto-select raw → rollup_1m → rollup_1h and say so in a source column. A drill that needs expired raw samples raises, naming the boundary — never a silent empty result; ash.status() exposes each tier's retention_start so callers can see it coming.

self-describing

Every function's catalog comment states the unit, the column contract, and the recommended next call — an agent can navigate from \df+ alone.

*

The asterisk in CPU* is load-bearing. An active backend reporting no wait event is either genuinely on CPU or in an uninstrumented code path. CPU* is the spelling everywhere — outputs, filters, legends — and must never be "cleaned up" to CPU.

§6

removed in 2.0

2.0 is a breaking release. Every v1.x reader has a more capable, uniform replacement; sampling, storage, rollups and admin functions are untouched.
